# Command reference

`ducktools help` answers what the tool can do, so nothing else has to keep a copy of that answer.

## What changed, and why

**`ducktools help`.** With no argument it prints every command grouped by purpose — reading,
structure, checking, editing, workspace, other — as a Command/Purpose table, preceded by the one
rule that applies throughout: a command taking `<project>` accepts either a path to a `.yaml` file
or the identifier of a registered project. With a command name it prints that command's usage line,
its purpose, and its arguments. An unknown name says so and falls back to the full reference.

It reads no project file and no settings, so it answers before anything is registered — which is
the situation a new install is actually in.

**The `claude` installation method copies nothing.** It previously appended a section per project
to `~/.claude/CLAUDE.md`, each one naming that project's path and enumerating the MCP tools
available at the time of writing. Both are snapshots of state that changes: the tool list went
stale on every release that added a command, and nothing reported that it had. The method now
writes a single section that names no projects and no tools, points at `list-projects` and `help`
as the way to find both, and collapses per-project sections left by earlier installs into that one.

**`grep` reports the project's root file twice.** A regression, and this entry originally described
it as a new capability, which it was not: the root file was already covered by the term walk and
has always been searched. 0.10.1 prepends it to that walk a second time, so any match in the root —
a goal, a setting, an `ai_instruction`, an entry in `uses` — comes back as two identical rows.
Fixed in 0.10.2.

**Authoring methods on the resolver.** `add_rule`, `remove_rule`, `move_rule`, `create_term`,
`rename_term` and `remove_term` are present on the resolver but are not wired to the CLI or the MCP
server, so this version exposes no way to call them. They carry no behavior for a consumer of
0.10.1.

## Migrating a project

Nothing to do. No format changed and no command was removed or renamed.

An install that registered through the `claude` method carries per-project sections listing MCP
tool names. That list is already incomplete. Re-running the installation's Claude method replaces
those sections with a single one that stays correct because it enumerates nothing.

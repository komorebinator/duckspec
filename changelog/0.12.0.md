# A workflow is a map of how work is done

Until now a `@DuckWorkflow` was a delivery pipeline a project picked by name —
`@GitWorkflow`, `@GitHubWorkflow`, `@GerritWorkflow` — with commit, submit and
release built into it. That fits a project whose practice is one of those three
and nothing else. It could not describe a project that tries changes on one
branch, builds on a schedule and promotes an image by hand, and it said nothing
at all about where a change stands.

A workflow is now a map of how work is done on a project, the kind of thing a
contributing page would otherwise hold: the states a change passes through,
the branches and channels involved, and the rules that hold along the way. A
person or a model reading it can tell where the change in hand stands and what
to do next.

This release breaks consuming projects; see "Moving onto 0.12.0" below.

## What changed

### Workflows

- `DuckVersion` is renamed `DuckFlow`, since it now holds the practice as a
  whole rather than version calculation.
- `@WorkflowStep` is one state of a change: a `when` that can be checked
  against something observable, and the `operation` that moves the change on.
  Steps are listed in the order work passes through them; where a change
  stands is found by evaluating every `when` — it sits at the last one that
  holds, and a step that did not happen stays visibly unsatisfied.
- `@Branch` and `@Channel` (with `from`) say which branches play a part and
  through which names people receive what is shipped.
- Operations are recipes on the systems that perform them: `@Git`, `@GitHub`,
  `@Gerrit` and the new `@Jira`. A step names one as
  `@<TermName>#<recipe>(<argument>=<value>)`, and `verify_project` reports a
  step whose `operation` is not such a call (`broken-operation`).
- `@GitHubWorkflow` stays, as the typical minimal practice and the worked
  example to copy from. `@GitWorkflow` and `@GerritWorkflow` are removed: a
  project whose practice differs writes its own workflow whole.
- `versioning` belongs to the workflow instead of the project, and
  `@DuckspecProject#prepare_release` replaces the project's `submit` and
  `release` recipes: it writes the version and the changelog entry and records
  them as a change like any other, which then travels the workflow's steps.
- The backtick rule for term references in text that reaches GitHub now sits
  on `@GitHub`.
- `@DuckspecWorkflow` describes how the framework itself is worked on. Outside
  contributions come as pull requests from a fork; before anything reaches
  main, every registered consumer is verified against it
  (`@Duckspec#verify_consumers`), because main is what consumers receive.

### DuckTools

- `load_terms` returns each term with its `extends` chain only and names the
  terms it mentions instead of loading them. Following mentions reached the
  whole corpus from any term.
- `load_workflow` reads the configured workflow; `load_project` shows only a
  pointer to it.
- `add_item`, `set_item`, `remove_item` and `move_item` edit bare-string lists
  — guidelines, instructions, goals, `uses` — at any depth, and replace the
  rule-only operations. `add_entry` writes nested blocks, so a function with
  its `arguments` is added in one call.
- `verify_project` checks a term's own top-level fields against its `extends`
  chain and reports a `uses:` entry that resolves to nothing (`broken-uses`).
  A bug introduced along the way made every project file skip the reference
  checks; it is fixed and covered by a test.
- The installer clones over https.

## Moving onto 0.12.0

- Move `versioning:` out of the project file into its `workflow:` block.
- If the project names `@GitWorkflow` or `@GerritWorkflow`, write a workflow
  of its own that extends `@DuckWorkflow`, using the steps of `@GitHubWorkflow`
  as the example and the recipes of `@Git` or `@Gerrit` as operations.
- Replace any call to the project's `submit` or `release` recipe with the
  workflow's steps and `@DuckspecProject#prepare_release`.
- Run `verify_project` on the project from its root file; it names every
  field that no longer has a declaration.

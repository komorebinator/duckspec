# Term references stop notifying strangers

A `@<TermName>` reference is how this framework names a term, and the
guidelines ask for it in preference to concrete syntax. GitHub reads the same
`@name` as a mention of one of its users — it links it, notifies whoever holds
that account, and for a `Co-Authored-By:` trailer credits them as a
contributor of the repository.

The names here are ordinary words, so they are taken. `Key`, `File`, `Term`,
`Page`, `Application`, `SemVer`, `Token` and `Git` are all live accounts held
by people with no connection to this project. The release notes for 0.11.0
carried twenty-four references across nineteen distinct names, eight of them
real, and notified those people about a framework they have never heard of.

GitHub applies the same parsing to commit messages, which are git data written
where GitHub has no part, and no setting disables it at repository,
organisation or account level. The only point of control is the text itself.

## What changed

`@GitHubWorkflow` gains one guideline: text leaving for GitHub — commit
messages, changelog entries that become release notes, pull request and issue
bodies — wraps term references in backticks, which GitHub does not parse for
mentions.

Nothing about the reference syntax changes and nothing is given up. A term
reference is an identifier in a formal grammar; marking it as code says
exactly that, and it reads the same either way:

```text
@DuckWorkflow      linked as a user, notification sent
`@DuckWorkflow`    plain text, nothing happens
```

Term files are unaffected — GitHub does not render `.yaml` as markdown. The
collision exists only where text crosses out of the spec and into a page
GitHub formats.

The rule sits on `@GitHubWorkflow` rather than on `@DuckWorkflow`, because it
describes one platform's behaviour. Neither Gerrit nor plain git parses
mentions, and their workflows do not carry a constraint that only makes sense
somewhere else.

## Not changed

The 0.11.0 release notes are left as published. Editing them would not
un-notify anyone, and rewriting the commit that carried the `Co-Authored-By:`
trailer would mean force-pushing published history for no benefit anyone can
still collect.

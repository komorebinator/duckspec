# Verification that verifies

A clean report used to mean either "everything here is correct" or "nothing here was
read", with no way to tell which. It now means the first, and the second is reported.

## What changed, and why

**`unknown-field` reaches mappings.** It read lists of entries and nothing else, so
`settings:`, `workflow:` and `versioning:` — three mappings on every project — were
never checked at all. `_slot_mapping` reads them, taking the type from the slot or from
the mapping's own `type:` key.

**A slot's `type:` is read wherever it sits.** It had to be the line immediately after
`- id:`; a slot written description-first silently counted as untyped, and everything in
it went unchecked. Order no longer matters.

**Slots that hold entries declare what they hold.** `arguments` on @Recipe and @Function,
`build_args` on @ContainerImage, `parameters` on @Signal and `variables` on @Template are
@Property; `stages` is the new @ContainerImageStage, which carries the base image a stage
builds on. `settings`, `workflow` and `versioning` name their types too.

**`untyped-slot` reports what no check reads.** Opt-in, because a project mid-migration
lights up everywhere. It is the only thing standing between a clean run and a clean run
that read nothing.

**`verify-source` settles the mechanical half of @DuckspecProject#verify_source** —
declared paths exist, named functions are present in the source their component points
at, file or folder alike. Ids that name a role rather than a symbol are skipped via
`implicit_functions`, declared on the type: `run` on @Script, `on_click` on @Button.
Whether a description is true of the code remains a reading task, and remains the recipe.

**`add_entry` appends an entry to a slot**, taking the item column from the entries
already there and quoting values that would otherwise read as structure. Adding a
property or a function previously meant hand-writing the block.

**Every public resolver operation has a test.** `check_operations` exercises all
twenty-five against a throwaway project and fails naming any that has no check, so an
untested operation cannot be added. The nine that write to term files had none.

**`commit` joins `submit` and `release`**, recording work locally and going no further.
All three now run @DuckspecProject#validate first, which gained a test-coverage pass and
runs a software's whole suite when its sources changed.

**Two guidelines are gone.** The one requiring `Invoke @<Term>#<recipe>()` to resolve is
enforced by `broken-path-ref` without exemptions. The one deciding whether a term belongs
to the framework or to a project failed at that job: thirty unused terms passed it, since
it filtered for platform-specific and the problem was speculative.

**A guideline was wrong.** Paths were said to be relative to the file they appear in.
That holds for `terms_folder`, `uses` and `settings`, but a `src:` resolves against the
project's `settings.src` no matter how deep the term sits.

**Commit messages carry what changed and why**, being what a changelog entry is written
from — and @DuckspecProject#release now drafts from the log rather than from the diff,
which shows what moved but never why.

## Migrating a project

1. **Run `verify-project`.** Expect new `unknown-field` errors in two places: inside
   `settings:`, `workflow:` and `versioning:`, and inside slots whose `type:` was not on
   the line after their id. Both were unchecked before, so the errors are pre-existing
   defects surfacing, not new breakage.
2. **Run `verify-project --untyped`** to see which slots still hold entries nothing reads,
   and declare `type: @X` on the ones with a fixed shape. A slot whose keys vary with the
   thing it sits on cannot have one and stays unverified.
3. **Run `verify-source`.** If it reports a function that plainly is not a symbol in the
   source — a script's entry point, a handler attached inline — declare that id in
   `implicit_functions` on the type rather than removing the entry.
4. **Requests to commit now map to @DuckWorkflow#commit**, which stops at local history.
   Only `submit`, `push` and `send` deliver.

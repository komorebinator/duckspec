# Rule and term-file operations reach the front ends

The six operations introduced in 0.10.1 — `add-rule`, `remove-rule`, `move-rule`, `create-term`,
`rename-term`, `remove-term` — existed in the resolver and were fully documented, but neither the
CLI nor the MCP server called them, so nothing outside could reach them. They are wired now and
appear in `ducktools help`. No migration is needed; the format is unchanged.

## What changed, and why

**The six operations are callable.** Editing a rule block, and creating, renaming or deleting a
term file, are available from both front ends instead of only from inside the library.

**A test guards against it recurring.** Comparing the spec with the code confirms a method is
*described*; it says nothing about whether anything calls it, which is why two releases shipped
with the gap and both surfaces still looked complete. `check_wiring.py` compares the resolver's
public methods against the ones the CLI and MCP server actually invoke, and fails naming the
orphans.

# Identity and schema

Entries are identified by `id`. A term is identified by its filename. `contains:` and `properties:`
become one block. Nothing is required anywhere. Every term is rooted at `@Term`.

## What changed, and why

**Entries carry `id`, not `name`.** `name` had been doing two jobs — the identifier a `#`-path
addresses, and a human label — and they follow different rules. A component id is `main-window`, a
function id must match the identifier in the source verbatim, a term's identity is CamelCase.
Splitting them lets each be itself. An `id` is unique among its siblings, not within the file:
`run` appears once per script, `on_click` once per button, and `#`-paths resolve by narrowing, so
`@ImageBuild#cleanup#run` is unambiguous while `@ImageBuild#run` is now reported as ambiguous.

**`name` is optional and never an identifier.** A term's identity is its filename, which is what
`@TermName` references have always resolved against. Set `name` where a display name differs
usefully from the id — a project, a piece of software — and omit it where it would restate it.

**`contains:` merged into `properties:`.** The two blocks held the same kind of thing with no rule
for which to use: lists appeared in both, term references appeared in both. One block remains,
carrying the meaning of `contains:` ("named slots that things of this type fill") under the name
`properties:`.

**Nothing is required.** `required:` is gone, with the two checks that read it. What the checker
verifies is that *what is written* is true and consistent with itself, never that everything was
written. Completeness is the author's business.

**Every term extends something; `@Term` is the root.** `@Term` declares `id`, `name` and
`description` once and everything inherits them, so no type restates them. This is what lets the
checker see a member shadowing an inherited one, including the universal slots (`properties`,
`recipes`, `guidelines`, `lists`).

**Slots declare their element type** with `type: @X`, replacing inference from the slot's prose,
which could not tell a list of entries from a scalar field whose description mentioned a term.

**`@ElementState` assigns values through `property_changes:`** — a mapping of property to the value
it takes while the condition holds. Previously a condition was written into the value itself
(`disabled: (when the list is empty)`), leaving boolean fields holding prose.

**New terms.** `@ExternalProject` for a project you depend on but do not develop: built on
`@Project`, so it inherits the descriptive shape without the delivery lifecycle — there is no
`release` to invoke on someone else's project. `@ElementState` for a named condition under which an
element takes different values.

**`@Key` is a `@File`.** A key stored in the filesystem has an install `path`; it previously
extended `@DesignPattern` and had none. Its `format` became `encoding`, leaving `format` to mean
the file format.

**Checks.** Added `unknown-field` (an entry setting a field no type it has declares) and
`ambiguous-path-ref` (a segment matching more than one entry). Removed `name-mismatch`,
`missing-required-property` and `missing-required-field`.

**Commands.** `schema`, `uses`, `query` and `entries` answer structural questions that previously
meant reading files by hand. `set` and `remove` edit by `#`-path and refuse an ambiguous one. Every
command accepts a registered project identifier in place of a path, so none depends on the working
directory.

## Migrating a project

The resolver accepts both `id:` and `name:` on entries, so a project keeps working until migrated.
Run `ducktools verify-project <project>` after each step.

1. **Rename list entries** — every `- name:` nested under a slot becomes `- id:`. Leave `name` in
   free text alone, and leave `- repository:` entries in `references:` untouched.
2. **Drop the top-level `name:`** from each term file. Add one back only where a display name says
   something the filename does not.
3. **Merge `contains:` into `properties:`** — move the entries, delete the block.
4. **Delete every `required:`.**
5. **Add `extends:` to any term that lacks one**, pointing at `@Term` unless a more specific parent
   applies.
6. **Delete `id` and `description` declarations an ancestor already declares** — reported as
   `redeclared-member`.
7. **Declare `type: @X` on slots that hold named entries.**
8. **Convert element states** — a property assigned under a condition moves into
   `property_changes:`, and the property itself goes back to holding a value.
9. **Resolve `unknown-field`** — either the field belongs on a type that should declare it, or the
   entry names the wrong `type:`.
